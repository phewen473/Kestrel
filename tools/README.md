# tools - scripts to run by hand

Run them from the repository root. All of them write into `results/`.

## demo.py - send one message and look at it

```
python tools/demo.py --text "CQ CQ de Q1AAAA" --snr -15 --condition moderate
```

Builds one frame, passes it through the simulated channel, and decodes it. It prints what the receiver found and writes:

- `results/demo.wav` - what the receiver heard. Play it, or feed it to any waterfall program.
- `results/demo_waterfall.png` - a picture of the signature tone pattern and the tones that follow.

Options: `--text`, `--level` (0 to 4), `--snr` (dB in 2.5 kHz), `--condition` (`awgn`, `good`, `moderate`, `poor`), `--offset` (Hz), `--seed`.

## snr_sweep.py - measure L0 decode rate against SNR, with and without fading

```
python tools/snr_sweep.py --trials 40
```

Sends many random 40-character messages at each SNR value under each channel condition and counts how many decode. It writes `results/l0_snr_sweep.csv` (the numbers) and `results/l0_snr_sweep.png` (the chart). The full run takes about ten minutes on two processor cores; use `--conditions awgn` for a quick noise-only run.

## level_sweep.py - measure every speed level

```
python tools/level_sweep.py --trials 40
```

Does the same in noise only for each speed level, L0 to L4. It writes `results/levels_snr_sweep.csv` and `results/levels_snr_sweep.png`. The lowest SNR at which every frame decodes is what `modem/levels.py` records for each level. It takes a few minutes.

## fading_sweep.py - measure every speed level with fading

```
python tools/fading_sweep.py --trials 40
```

Sends random messages at every level through noise only and through light, moderate and heavy fading, across a range of SNR values. For each point it records how many frames decoded, how far the receiver's own SNR reading was from the truth, and the receiver's fading index. It writes `results/levels_fading_sweep.csv` and `results/levels_fading_sweep.png`. The lowest SNR at which nine frames in ten decode in the worst of the three fading conditions is what `modem/levels.py` records as each level's fading limit. It takes about twenty minutes on two processor cores.

## decode_wav.py - decode a recording

```
python tools/decode_wav.py local/recordings/rx_20261121_010000Z_Q1AAAA.wav --csv found.csv
```

Plays a WAV file (any sample rate, mono or stereo) through the same receiver the panel uses and lists every frame decoded and every Kestrel signature heard but too weak or faded to read, with the time into the recording, level, signal strength and audio offset. `--csv` also saves the list as a table. It runs at about twice real time: an hour's recording takes about half an hour. The panel offers the same thing as File > Decode a recording, which saves the table beside the WAV file.

Recordings come from the panel's Settings > Logging > Record received audio. Turn it on for every on-air test: if two stations hear nothing, the recordings show whether a signal arrived at all.

## bottom_study.py - how slow must a level below L0 be? (roadmap step 2)

```
python tools/bottom_study.py --trials 40 [--only 0 1 2] [--conditions awgn good] [--snrs -24 -26]
```

Sends beacons through the channel simulator in noise and in light, moderate and heavy fading, with up to 2 Hz of frequency error, and counts how many decode. Candidates 0 to 4 are today's L0 beacon with each tone held longer (0.4, 0.8, 1.6 and 3.2 s) and the tones 1.25 to 5 Hz apart; candidate 5 is the real long beacon of signal version 0.27, received by the full receiver. Writes results/bottom_study*.csv. `--only`, `--conditions` and `--snrs` split the work so many processes can run side by side (a full run is several hours on one core).

Results (November 21, 2026, 40 beacons a point): longer tones gain the expected 3 dB per doubling on a steady path (1.6 s tones: -28 dB, 125 s); tones 1.25 Hz apart lose about 6 dB in heavy fading against 2.5 Hz apart; no timed slots were needed. The long beacon chosen for 0.27 (59.5 s) decodes every time down to -25.6 dB on a steady path and nine in ten down to -18.6 dB in the worst fading, against -21 and -14 dB for an L0 beacon.

## combine_study.py - how much further do repeated long beacons reach when added together?

```
python tools/combine_study.py --condition poor --snrs -24 -26 --trials 40
python tools/combine_study.py --noise 600        (false alarms on an empty band)
```

Each trial sends four copies of one station's long beacon through the channel simulator, each with its own noise and fading, and gives them one at a time to the receiver's combiner, recording after how many copies the beacon decoded. Results (November 21, 2026, results/combine_study.csv): on a steady path one copy always decodes at -26 dB, two at -28 (39 of 40), three at -28, four at -29; in the worst of the three fading conditions nine in ten decode at -20 dB with one copy, -24 with two or three, and -26 with four. 9,600 stretches of noise alone produced no decode.

## signal_report.py - summarize the signal logs

```
python tools/signal_report.py %LOCALAPPDATA%\Kestrel\logs\signal --since 2026-11-21 --csv-dir report --redecode
```

Reads the signal logs (Settings > Logging > Signal log in the panel; File > Open the signal log folder) and prints a report: sessions; frames received by level with SNR, fading, offset, drift and which header copy was read; stations heard; near misses (with how many were likely Kestrel by the tone test, logs from 0.31R2 on); how far strong preamble candidates got (no header, header but the body failed, decoded); decodes and near misses by UTC hour and band; transmissions with drive, peak level and the radio's power, ALC and SWR; received audio level, sound-card dropouts and clock drift. `--csv-dir` writes each kind of event as a CSV table for a spreadsheet; `--redecode` decodes every saved clip again and says which now decode or no longer do, to check a receiver change against real signals.

The signal log itself is described at the top of `live/signallog.py`. It is off by default. "On" writes text only: about a line a minute on a quiet band and a few more per signal, a few megabytes a day. "On, with each frame's audio" also saves a WAV clip of every frame and near miss (an L0 frame is about 6 MB); clips are removed after 14 days and kept under 500 MB in total, oldest first. The hourly recordings are a separate setting and the largest, about 86 MB an hour.

`decode_wav.py --signal-log FOLDER [--clips]` writes the same log for a recording decoded afterwards.

## link_demo.py - watch two stations hold a contact

```
python tools/link_demo.py --scenario slip
```

Runs two simulated stations through a whole contact (beacon, answer, lock, messages both ways, close) while the radio path changes, prints every transmission and each station's decisions, and writes `results/link_<scenario>.png`. Scenarios: `steady`, `asymmetric` (one direction strong, one weak), `slip` (conditions fall away and come back), `dropout` (the path vanishes for a minute and a half), `fading`, `dead` (the path dies for good), and `group` (three stations answer one beacon and the caller works each in turn).

## live_devices.py, live_monitor.py, live_send.py, live_station.py - Kestrel on a sound card

These four work with real audio and need the `sounddevice` package (and `pyserial` for serial-port keying); both are in `requirements.txt`. See `live/README.md` for how they fit together, rig control, and a no-radio test with audio cables.

```
python tools/live_devices.py                                           (list the sound devices; give the other tools part of a NAME, since Windows renumbers devices)
python tools/live_monitor.py --in "USB Audio"                          (receive only: print every Kestrel frame heard)
python tools/live_send.py --call Q1AAAA --grid EM92 --out "USB Audio"  (transmit one beacon)
python tools/live_station.py --call Q1AAAA --grid EM92 --beacon --send "Hello"   (a whole contact, in real time)
```

```
python tools/kestrel_panel.py                                          (the control panel: the same things, with menus, meters and a logbook)
python tools/kestrel_panel.py --profile second                         (a second panel with its own settings, for a second radio on the same computer)
python tools/live_frequencies.py                                       (show the frequency list; --add and --remove your own)
python tools/preamble_study.py                                         (compare the chirp pair with a tone-pattern preamble; several minutes)
```

`kestrel_panel.py` is the control panel. It starts listening as soon as it opens (Settings > Operating can choose Monitor or nothing instead); the first time, it opens Settings so the callsign, grid, radio and sound devices can be filled in. How it is laid out:

- **Menus and keyboard:** every function is on a menu (File, Operate, Messages, Stations, View, Settings, Help), so the panel can be run without a mouse. Alt and the underlined letter opens a menu; the function keys and Ctrl shortcuts are listed under **Help > Keyboard shortcuts** (F1). F2 Listen, F3 Monitor, F4 Off, F5 beacon on/off, F6 call the station in To, F7 end the contact, F8 stations heard in the last 48 hours, F9 telemetry received, F10 mail held and carried, F11 broadcast, F12 Settings, Ctrl+Y respond to the selected station; Alt+1 to Alt+9 and Alt+0 quick messages 1 to 10 (Ctrl+1 to 3 for the first three), Ctrl+4 and Ctrl+5 telemetry, Ctrl+L the To box, Ctrl+M the message box, Ctrl+R the frequency list, Ctrl+Up and Ctrl+Down the previous and next frequency, Ctrl+G the stations list, Ctrl+J the level sliders.
- **Help > About Kestrel:** the signal version (two stations must match to hear each other), the specification version, the program's commit number and date, and the Python version. The title bar shows both: "Kestrel 0.28 - signal v0.27" means program version 0.28 sending signal version 0.27 (0.28 changed only the receiver).
- **Radio mode** (Settings > Radio): Automatic (USB-D if the radio has it, otherwise plain USB), USB-D, or USB. Kestrel uses upper sideband on every band and never lower sideband. On plain USB turn the radio's speech processor and transmit equaliser off.
- **Rig type:** the list loads in the background when Settings opens (the first time on a computer it can take up to a minute while an antivirus program checks rigctld). Pick the radio from the list, or type part of its name to narrow it; text that is not an entry of the list is refused when you save.
- **Settings** (a window with tabs, F12): *Station* (callsign, grid, your name and a rig description for quick messages and the log, the radio's full power in watts); *Radio* (radio type from Hamlib's list, CAT serial port, speed and handshake, how the transmitter is keyed and the port for RTS or DTR, the rigctld program or one already running); *Audio* (the sound devices to and from the radio); *Operating* (what the panel does when it opens, the repeating beacon's interval and its automatic stop); *Logging* (level of detail, recording of the received audio, and the signal log for analysis); *Quick messages*; *Appearance* (theme). The panel starts and stops Hamlib's `rigctld` itself for the radio chosen. The Radio tab says how many radio types are listed; if the list is empty it says why in red (rigctld missing, moved, blocked by an antivirus program, or slow to answer) and the log keeps the reason. If the rigctld in the settings is gone, the copy installed with Kestrel is used instead. "Reload rig list" fills the list again after the cause is fixed, and Browse reloads it from the program chosen.
- **Mode: Listen / Monitor / Off.** Listen just listens: nothing is transmitted unless you start it (beacon, Respond, call, message or broadcast); replies to your own beacon or call are accepted, and a contact you started or accepted runs by itself. Monitor receives only; Off stops both. Beacon, Call station and Broadcast switch to Listen by themselves if needed.
- **Beacon type** (Operate > Beacon type, or Settings > Operating): *Short* (the default) is the call-up others can answer. *Long* sends the long beacon instead: about 60 seconds, heard 4 to 5 dB further down than a short beacon, answered by nobody (stations that hear it show it to their operator, who may respond). Long beacons repeat no more often than every 10 minutes. The button reads "Long beacon (reach)" while Long is chosen. A long beacon heard from another station is highlighted in Stations heard like a beacon, marked "sent a long beacon".
- **Listen before transmitting** (Settings > Operating, on by default): a beacon, long beacon, directed call or broadcast waits while another signal is heard where it would go; the status band shows "WAITING - frequency in use" and the log says when it clears. Replies inside a contact are never held. Signals weaker than about -10 dB may not be noticed, so the frequency is still yours to check. A change takes effect the next time Listen starts.
- **Long beacons heard:** a long beacon too weak to read alone is kept and added to the next ones from the same station; when they decode together the log says "heard long beacon (2 copies added together)". Steady carriers on top of a long beacon are removed automatically.
- **Beacon (call anyone):** a push-on, push-off button. Pushed in, the station sends one beacon and listens for answers, then listens normally until the next round, every 5 minutes by default (Settings > Operating: 5 to 60 minutes). Nothing goes out until the button is first pressed. Rounds pause during a contact; the interval starts again when the contact ends. Push the button again (or F5) to stop. The repeating stops by itself after 2 hours with no keyboard or mouse use (15 minutes to 12 hours, or never). The label beside the button counts down to the next round.
- **Available / Unavailable (Ctrl+U):** a push-on, push-off button, remembered between sessions. Unavailable shows at the top right. While unavailable, your beacons are presence beacons (they say you are on the air but not taking contacts, and nobody answers them), and a station calling you by name gets one short "not available" reply, after which it stops calling. The Stations heard list's "Status and messages" column shows each station's last known availability (from its beacons, or from such a reply). If you leave the station unavailable with nobody at the controls, that reply is automatic operation, which belongs inside the 97.221(b) segments; from version 0.29 the Kestrel calling frequencies are outside them, so switch to Off or Monitor when you leave the station.
- **Beacons and calls to you: you choose.** Listen does not answer anything by itself. A station heard beaconing, or calling your callsign by name (marked CALLING YOU), is highlighted in the Stations heard list for five minutes, with a bell and a line in the log. The list's Messages column shows whether you have messages waiting for that station (by name, or for any partner), and whether its beacon says it holds mail (which may be for you) or is asking for its own mail. To answer, select the station and press **Respond** (Ctrl+Y): the panel calls it by name. A station still waiting for answers to its beacon, or still calling you, accepts that call at once. Settings > Operating can switch to answering every beacon and call automatically.
- **Call station (F6):** calls the station in the To box by name. If the station is busy when you press it, the call waits, and the log says so. Pressed during a contact, it is made when that contact ends. Pressed during a beacon round or an answer, it is dropped if a contact starts first (and always if the contact is with the station you meant to call), so an old call never goes out by surprise. Switching to Monitor or Off cancels a waiting call.
- **Frequency list:** Kestrel's calling frequencies (80 m 3582.5, 40 m 7110.0, 30 m 10147.0, 20 m 14112.5 kHz; moved in version 0.29 to an area away from other modes' calling frequencies) plus your own ("Add..." and "Remove"). A frequency whose signal would fall outside the U.S. amateur data segments cannot be added, and Listen will not start on one; Monitor still can. Choosing a frequency tunes the radio to it, with a 3000 Hz receive filter, and restarts the receiver there. A change is refused during a contact.
- **Status band:** the station's state in large letters. A lock shows as a solid green band naming the partner; trouble holding the link turns it amber, a failure red. Under it, one line gives the partner's signal strength, whether it is steady or fading, the speed level in each direction, and how many messages are waiting and received.
- **Stop calling (Esc):** stops what your station started that has not made a contact: a call made with Respond (Ctrl+Y) or Call station (F6), a call still waiting for the station to be free, a beacon round and the repeating beacon, a waiting long beacon, and broadcast frames not yet sent. A call, beacon, long beacon, mail notice or broadcast frame on the air at that moment is cut short and the transmitter comes off at once. The station goes back to listening. A contact in progress is left alone: End contact (F7) closes it properly. Also on Operate > Stop calling, and F7 does the same when no contact is in progress.
- **Keep contact open / End contact / Once locked:** tick "Keep contact open" to hold the lock after the traffic is done; "End contact" closes it properly. "Once locked" chooses whether the pair stay on the calling frequency or move to Channel 1, 2, 3 or 4 (2.5 kHz apart above the calling frequency; one channel on 30 m) and return at the end (needs rig control).
- **Idle working frequency:** if no message passes for two minutes on a working frequency, the station that proposed the move shows a warning; a minute later the contact is closed and both radios return to the calling frequency. OK only takes the warning away.
- **To / Quick / Message / Queue / Broadcast to ALL:** a callsign in the To box makes a queued message go only to that station (blank means whoever the partner is). "Quick" offers up to 10 ready-made messages, each with a name you choose, filled in from Settings when used ({call}, {name}, {grid}, {rig}, {power}, {to}, {telemetry}). Settings > Quick messages lists them with Add, Edit, Delete, Move up and Move down (double-click a row to edit; changes are kept when you press Save); the Add/Edit window shows what the message would read right now. Alt+1 to Alt+9 and Alt+0 use them in list order (Ctrl+1 to 3 still work for the first three); they are also under Messages > Quick messages. The three quick messages of earlier versions are carried over, named "Call, name and grid", "Rig and power" and "Telemetry". A quick message goes into the Message box to be checked, then Enter queues it or F11 broadcasts it. "Broadcast to ALL" sends the message to every station listening, at the slowest level, with no acknowledgment.
- **Messages to send, Band column:** beside each message, the band its station was last heard on (in the last 48 hours, else the band saved with the contact; blank if never heard). For a message to the partner, or a broadcast, the band the radio is on. It follows the station: heard again on another band, the row changes.
- **Edit message / Delete message (Del):** buttons under "Messages to send", and the same two choices on a right click anywhere in the list (over a message, it is selected first).
- **Select all / Copy / Clear on the right-click menus:** in Messages to send, Stations heard and the Activity log. Select all (Ctrl+A) chooses every row (every line of the log). Copy (Ctrl+C) puts the chosen rows on the clipboard, headings first and columns separated by tabs, so they paste straight into a spreadsheet (no rows chosen: the whole list; in the log, the selected text or the whole log). Clear: in Messages to send, *Clear finished messages* takes delivered and sent messages off the list and keeps those still waiting; in Stations heard, *Clear stations heard* empties the list but keeps your saved contacts (the 48-hour record, F8, is untouched); in the log, *Clear* empties the window (the logbook and signal log are untouched). Edit changes the address and text of one message that is still waiting. For Delete, select one or more rows and press the button or the Delete key. A waiting message is taken out of the queue (and out of the saved queue that survives closing the panel); a finished one is only cleared from the list; one that is being sent is left alone.
- **Store and forward (since 0.30).** A message for a station that is not on the air does not just wait: in any contact your station hands a copy to the partner to carry, and the row shows "waiting (carried by Q2BB)". The carrier delivers it when the station it is for beacons or calls, and the receipt that comes back marks your row "delivered (receipt from ...)". Settings > Operating > **Carry mail for others** (on by default) lets your station do the same for others. **Stations > Mail held and carried** (F10) lists mail you hold for others (who it is for, its message ID, who handed it over, time left, who else carries it; never its content) and your own messages out with carriers. A station's mail notice shows in the Stations heard status column ("holds mail for YOU, Q6FF; hears ..."). Mail lives 62 hours and is kept in a file per callsign between runs. A message already with carriers cannot be edited (delete it and write a new one). The Activity log's technical details and the signal log show the length of other stations' messages, not their text.
- **Telemetry:** Messages > Send telemetry to the station in To (Ctrl+4) or Broadcast telemetry to ALL (Ctrl+5) sends what this station hears: its grid, power, and each station heard in the last 30 minutes with its median signal and fastest level, in the TLM1 layout of spec Section 6.12. Telemetry received from others is listed under Stations > Telemetry received (F9), beside this station's own figures, ranked by how many stations each hears and how well: a guide to the best-placed station for net control.
- **Checks before transmitting:** changing the callsign in Settings asks you to confirm it exactly, and something that does not look like a callsign is refused. While transmitting, if the radio's ALC reads half its scale or more, the log says so once per transmission: lower the transmit slider (Ctrl+J) until ALC barely moves.
- **When the station stops by itself:** if something goes wrong while Listen or Monitor runs, the log says "stopped by a problem", the mode returns to Off, and the details (version, library and where it happened) are saved in a `problem_...txt` file beside the logbook. A fault inside the signal log is reported once and the station carries on.
- **Signals heard but not read:** when the receiver finds a clear Kestrel preamble but cannot read the frame, the log says "possible Kestrel signature heard" with a guess at the level and the audio frequency, and the logbook records it (advanced level and up). It means the other station is reaching you, just not strongly enough.
- **Recordings:** File > Open the recordings folder; File > Decode a recording plays one back through the receiver (see `decode_wav.py` above).
- **Signal log:** Settings > Logging > Signal log: Off (the default), On (text only, a few MB a day) or On with each frame's audio (capped at 500 MB, 14 days). File > Open the signal log folder; summarize it with `signal_report.py` above.
- **Stations heard:** the list on the main window shows every callsign decoded since the panel opened, plus saved contacts (marked `*`), with the **Band** each was heard on (a saved contact keeps the band it was last heard on, in `contacts.json`). A **right click** on a station offers Respond (call it), Save as contact, Remove contact and Show last 48 hours (every reception of that station in the last two days, with band and frequency). **Stations > Stations heard (last 48 hours)** (F8) shows the longer record, kept in `local/panel_heard.jsonl`: one row per station (first and last heard, times heard, last and best signal, fastest level, band, frequency), or every reception. Click a heading to sort; Enter or a double-click puts the callsign in To.
- **Contact book (since 0.31R3):** a record for each station you keep, in `contacts.json` (in `local/` from the source folder): callsign, name, location, grid locator (with distance and bearing from your grid), the other station's radio, power and antenna, notes, when and how it was last heard, and a **contact history**. **Add Contact** and **Edit Contact**, under the To box, work on the callsign in the To box (Edit Contact with an empty To box offers a list). A **double-click** on a station in Stations heard opens its record (and puts its callsign in To); a station not saved yet opens as a new record filled in from what was heard: callsign, grid locator, band, frequency, level and signal. Radio, power and antenna are not sent over the air, so they are filled in by hand. Save as contact (one station selected) opens the same window; Remove contact and Delete Contact... ask first, since the history goes too. The history has one line per stretch of traffic (all traffic within 15 minutes on one band): when, band, frequency, fastest level, how you heard them, how they reported hearing you, messages in and out, and how far it got (Heard beacon, Called, no answer, Contact, Contact, ended). **Settings > Contacts:** how many history entries each contact keeps (30 to 200, default 120; the oldest are dropped first, and lowering it trims after asking) and what is recorded (All traffic, or Completed contacts only). The book learns from the logbook at any level of detail (`live/contacts.py`).
- **Contacts and waiting messages:** "Save as contact" keeps a callsign for later (in `local/contacts.json`). A message queued for a callsign waits until that station is the partner. Waiting messages are kept in `local/` and come back when the panel is reopened.
- **Transmit scope (top):** a spectrum trace above a short waterfall of the audio Kestrel is sending to the radio, on the same 0 to 3000 Hz scale as the receive scope below it. Its left scale is dB below full scale. A line of words says what is being sent and the radio frequency its center lands on (dial plus 1500 Hz). When the transmission ends the picture stays, marked "last sent". It shows the audio leaving the program, not what the radio puts on the air.
- **Receive scope (bottom):** a spectrum trace above a waterfall of the receive audio. It is 720 points wide (about 4 Hz each) from a third of a second of audio (steps of 2.9 Hz), redrawn ten times a second; each point shows the strongest signal it covers, so a narrow tone is never lost.
- **Resizing the panels:** the three lists, the Activity log, the two scopes and the Levels meters are separated by dividers. Drag a divider to shrink one panel and grow its neighbor; the scopes redraw at whatever size they are given. The window's size and the dividers' places are remembered. View > Reset the panel sizes puts everything back. The starting layout fits a 1024 x 768 screen.
- **Font:** Settings > Appearance sets the font family and size (7 to 16) for the whole window, applied as soon as you save.
- **Help > Reading the scopes** explains the two scopes (this replaced the key that used to sit under them).
- **Floor and Range sliders:** beside each scope. Floor sets the level at the bottom of the trace and the black of the waterfall: raise it to hide noise, lower it to see weaker signals (receive: dB relative to the noise, default -5; transmit: dB below full scale, default -70). Range sets how many dB lie between the bottom and the top (default 55 receive, 70 transmit); fewer dB gives more contrast. The dB marks follow the sliders, the settings are remembered, and a double-click on a slider resets it.
- **Waterfall colors and the Color slider (since 0.31R4):** for each operator's eyesight. **View > Waterfall colors** picks the set of colors both waterfalls use: Classic (black, blue, yellow, red), two sets made to be read with color blindness (blue to yellow; purple to yellow), Heat (black, red, yellow, white), Gray, Gray reversed (dark signals on white) and High contrast (black, white, yellow). The third slider beside each scope, **Color** (0 to 100, default 50), shifts where the colors change: up, weaker signals already reach the bright colors; down, only strong signals do. Both are remembered; a double-click on Color puts it back at 50.
- **Scopes in step, and time marks (since 0.33):** the transmit waterfall scrolls with the receive waterfall all the time (an empty line while nothing is sent), so a transmission sits level with what was received at that moment. **View > Time marks on the scopes** (Ctrl+T) turns on or off a dotted line across both waterfalls every 5, 10, 15, 30 or 60 seconds (whichever suits each waterfall's height), labeled with the time, and the seconds-ago scale to their right. **View > Scope time marks in** chooses **UTC** or **Local time** (the computer's time zone, daylight saving time included); the corner of each waterfall shows which (UTC, or the local offset such as UTC-5). On, in UTC, by default; both choices are remembered.
- **Long notes (since 0.34):** for a station too weak to work any other way. Type up to 28 characters in the Message box, put the callsign in To (or choose **ALL** at the top of the To list, for every station) and press **Long note (reach)** (Ctrl+N; also Messages > Send the message as a long note). With To empty it asks you to choose. The note goes in minute-long frames, like the long beacon (a header and one frame per seven characters: two to five minutes on the air), when no contact is under way and the frequency is clear. The station it is for answers with a one-minute receipt; with no receipt within two and a half minutes the note is sent again, up to three times, and the other station adds the copies together, so each try reaches further. Messages to send shows its progress all the way, updated twice a second: "waiting to send (try 1/3)", "SENDING try 1/3, frame 2/4", "receipt due 2:13 (try 1/3, then try 2/3)" counting down, "no receipt; try 2/3 next", and at the end "DELIVERED (try 2/3)" or "NOT delivered (3 tries)"; the transmit scope's words say the same try and frame while it is on the air. Delete takes it back. **ALL** in the To list also works for an ordinary message: Queue message with ALL chosen sends it as a broadcast (after the usual check). Notes for you or for ALL appear under Messages received, marked "long note"; a sound is made.
- **Grid locators (since 0.33):** Stations heard shows the grid of any station whose beacon, long beacon, answer or directed call was heard (answers and calls carry it since 0.33). A saved contact's grid is kept up to date from what the station sends, and the Activity log says when it changes; the propagation window works from it.
- **Propagation (since 0.32):** Stations > Propagation (best band by hour)... (Ctrl+P), or a right click on a station > Propagation to this station. Predicts by ITU-R P.533 from your grid to the station's (or any grid typed in), for a month you choose: for every hour (UTC and local) and each band's Kestrel calling frequency, the reliability (per cent of days L0 works), the median SNR in 2.5 kHz, the fastest level expected and the path (NVIS, one hop, two hops or more), with the MUF and the best band. Power and the man-made noise where you are (quiet rural, rural, residential, city) are remembered. The **sunspot number** is taken from the prediction set shown under the settings with its **issue date**; type a number to use your own instead. **Update online** fetches NOAA's latest, and (since 0.34R1) today's measured sunspot number (KC2G's effective sunspot number, fitted to the world's ionosondes) and NOAA's space weather: for the current month the measured number is used in place of the prediction while it is under six hours old (the note beside the box says which, and gives the month's prediction too), and a red WARNING line appears under the settings for a radio blackout from a solar flare, a geomagnetic storm (Kp 5 or more) or a falling ionosphere. Nothing is fetched unless you press it; **Load update file...** takes a `sunspots*.json` file sent to you (it is copied into the updates folder), and **Open updates folder** shows where such files can also simply be placed. The newest set wins. **Check the bands now** (since 0.35) shows the short-path window from the nearest ionosonde sounded in the last hour (the highest usable frequency on the path and the bands below it), the WSPR and PSK Reporter activity between your area and the other station's in the last hour, by band, and how close the predictions have been to the stations you actually heard (Settings > Logging > Check the propagation predictions, on by default; the record is prop_check.csv in the Kestrel data folder). **Report stations heard to PSK Reporter** (Settings > Logging, off by default) sends each Kestrel station you decode to pskreporter.info as mode KESTREL. The activity line and the link readings now give each frame's **Doppler spread** (how fast the path is fading). A contact's record shows the **best band now** for it, with a Propagation... button. Needs the ITU program: from the source folder run `build_prop.py` once (the setup program includes it).
- **`build_prop.py`:** fetches the ITU-R Study Group 3 P.533 implementation at its pinned release (v14.3, commit checked) with Git, compiles ITURHFProp, P533 and P372 with gcc (MSYS2's MinGW gcc on Windows) and copies them with their data files (about 140 MB) to `live/_prop/` (git-ignored). `--source FOLDER` uses a copy already fetched; `--target` puts it elsewhere (the setup program's `prop\`).
- **`waveform_study.py`:** compares candidate transmit waveforms before any becomes part of the signal: smoothed tone changes with faded ends (`shape25`, `shape50`), Gray-coded tones (`gray`), both, and other tone spacings for L0, L2 and L3. It measures each candidate's spectrum (99 % width, 40 dB width, power outside the tone band, also for a short frame) and the weakest SNR at which nine frames in ten decode, with noise only and on the sky-wave conditions (`good`, `moderate`, `poor`, `nvis`). Uses the Python modem. Results: `results/waveform_spectrum.csv` and `.png`, `results/waveform_study.csv`, `results/waveform_summary.csv`.
- **Zooming the scopes:** click a signal (or its callsign label) on the receive scope to center the view on it; turn the mouse wheel to zoom in or out about the pointer; or pick a width from the View box (full, 1000, 500 or 200 Hz). "Center on last signal" zooms in on the station decoded most recently; "Full view" or a right click shows everything again. Both scopes follow the same view. A view 600 Hz wide or narrower is made from 1.4 seconds of audio (steps of 0.73 Hz), which separates the long beacon's tones but runs about a second behind. The bottom scale is the audio frequency in Hz, the top scale the radio frequency each point is on, in kHz. The left scale is the signal's strength above the noise in dB; the right scale gives the waterfall's age in seconds. Dashed lines mark 500 and 2500 Hz, the Kestrel band. Each station decoded in the last minute is labeled with its callsign, over a bracket as wide as its signal.
- **Levels:** two vertical meters, receive (radio to PC) and transmit (PC to radio), in dB relative to the sound card's full scale, with a green target band (-30 to -15 dBFS average). The receive meter shows CLIP when the input reaches full scale: turn down the radio's USB audio output level. The slider beside it changes Windows' own recording level for the receive device (needs the `pycaw` package, which `setup_windows.bat` installs). The transmit slider sets the drive to the radio; while transmitting, the power, ALC and SWR the radio reports are shown under it, when the radio and Hamlib offer them.
- **Logging:** a CSV file per UTC day in `local/logs/` (File > Open today's log) and an ADIF file of completed contacts for logging programs. Three levels under Settings > Logging: *basic* (messages, broadcasts, telemetry, start and end of each contact), *advanced* (adds beacons and calls sent, stations heard, signal readings, rig and power) and *verbose* (every frame received or sent, the radio's meters, the input level and the settings in use). ADIF records use mode MFSK, with Kestrel and the signal version in the comment.
- **Theme:** View > Theme: System (follows Windows' light or dark setting), Light or Dark.
- **Activity:** the log in plain words; "Show technical details" shows every measurement and field. The full log is also kept in `local/panel.log` (or `local/panel_NAME.log` for a named profile).

Settings, your own frequencies, saved contacts, the 48-hour heard log and the logbook are kept in `local/`, which Git ignores.

`live_station.py` also takes `--call-station CALLSIGN` (in place of `--beacon` or `--listen`), `--to CALLSIGN` (the `--send` messages go only to that station) and `--broadcast TEXT` (sent to ALL first, unacknowledged). It takes `--keep-open` (hold the lock after the traffic), `--end-after SECONDS` (then close it properly) and `--move KHZ` (once locked, propose a working frequency that many kHz away; needs `--rig`).

`live_send.py` and `live_station.py` take `--ptt none|rig|cat|rts|dtr`, `--rig host:port`, `--band 40|30|20` (Kestrel's preselected frequency for that band), `--freq` (kHz), `--mode`, `--port`, `--baud` and `--gain`. Only transmit where your license allows, with the published specification matching the program.

`python tools/build_native.py` runs CMake on `cpp/`, builds libkestrel and copies it to
`modem/_native/`, where the modem loads it. Needs CMake and a C++17 compiler.

## make_spec_tables.py - write the specification's tables

```
python tools/make_spec_tables.py
```

Writes the tables that the specification refers to into `docs/spec/tables/`: the LDPC check lists for each frame size (`ldpc_checks_k402.txt` and so on) and the compression code of every character (`compression_codes.txt`). The tables come straight from the modem code, so the published description and the program cannot drift apart. Run it again whenever `modem/ldpc.py` or `modem/compress.py` changes.

## Preamble study

`preamble_study.py` compares the two-second chirp pair that starts every frame today with a short fixed pattern of each level's own tones. It changes nothing in the modem. For every level, at that level's weakest working signals (noise only, and moderate and heavy fading), it sends test frames with a random start and a random frequency error and records how often the true start is among the receiver's three best guesses, and how exact the timing and frequency are. Results go to `results/preamble_study.csv`.

First results (200 frames per point, November 18, 2026): a 12-tone pattern was found in 98 to 100 percent of frames at every level and condition, against 100 percent for the chirp pair (98 percent for the chirp 2 dB beyond L0's limit). The pattern would last 4.8 s at L0, 1.6 s at L1, 1.1 s at L2, 0.54 s at L3 and 0.27 s at L4, against 2 s for the chirp at every level, and would be as narrow as the level's data (160 Hz at L0) instead of 2 kHz. Not yet tested: telling the five patterns apart, false starts in long recordings and beside other signals, and whole frames decoded from the pattern's timing.
